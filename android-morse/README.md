## インストール

1. `dist/wabun-signal-0.3.5-debug.apk` をスマートフォンへコピーします。
2. スマートフォンのファイル管理アプリからAPKを開き、必要に応じて、そのファイル管理アプリからのインストールを許可します。
3. 「和文モールス送受信」を起動します。マイク・カメラは対応する機能を初めて使う際に許可します。

Android 8.0以上を対象とした試験用APKです。Playストア公開版ではありません。iPhoneではこのAPKは使用できません。

## 操作

上部の「送信」「受信」で画面を切り替えます。送信側には文章入力・TXT読込・音／ライトの送信、受信側には録音／動画の読込・マイク／カメラ受信と結果を配置しました。速度・音程は共通設定です。タブを切り替えると動作中の処理を停止し、入力・受信結果は保持します。下部の「すべて停止」は常に表示します。

|機能|操作と確認|
|---|---|
|音で送信|ひらがな・カタカナ（全角／半角）を入力し「音で送る」。送信前にひらがなで変換後の表記を確認します。メディア音量を調整してください。|
|テキスト入力|「テキストファイルを開く」でTXTを選ぶと、送る文章を置き換えます。UTF-8（BOM有無）、Shift_JIS（Windows-31J）、BOM付きUTF-16に対応。取り込み時は仮名をひらがなへ変換。取消・読込失敗では元の入力を保持します。自動送信はしません。|
|音声ファイル生成|「送信音をWAVファイルに保存」で16 kHz・モノラル・PCM16の音声を保存します。|
|録音から受信|送信側と同じ短点時間と音程を指定し「録音ファイルを開く」。開始・終了秒で会話部分を除外できます。最大30分です。|
|マイクで受信|「マイクで受信する」。まず通話なしで別の機器から音を再生して試します。入力レベルと音程一致の表示は正解率ではありません。|
|ライトで送信|文章を入力し「ライトで送る」。送信途中は「すべて停止」で消灯します。|
|カメラで受信|送信側と同じ光の短点時間を選び「カメラで受信する」。プレビュー中央の緑枠に光源を合わせ、明るさの境界を調整します。|
|動画から光を受信|「受信」→「動画ファイルを開く」。光の短点時間を送信側に合わせ、必要なら動画の開始・終了秒を指定します。動画内の音は解析せず、中央の緑枠内の平均輝度から点滅を読みます。カメラ・マイク権限は不要です。|
|結果の保存|「文章をコピー」または「結果をTXTに保存」。仮名はひらがなで出力し、TXTは受信本文だけをUTF-8で保存します。数字・記号・不明符号の□は保持します。|

音の初期設定は短点120 ms／700 Hz、光は短点300 msです。実機で信頼性を保証した値ではありません。音は180・240 ms、光は450・600 msへ遅くできます。送信側と受信側で合わせてください。長点は3倍、文字内の間隔は1倍、文字間は3倍、語間は7倍です。

丸括弧内も和文です。小書き仮名は通常サイズ、句点「。」は段落符号「」」へ変換します。元の小書きなどを完全に復元する機能はありません。英字は初期版の送信対象外です。送信は300符号までです。

テキスト読込はファイルサイズ64 KB以内です。漢数字は位取りを含めて数字へ変換します（一二三→123、十二→12、二百三→203、二千二十六→2026）。〇・零と一～九、十・百・千・万・億・兆に対応し、壱・弐などの大字や漢字の読みは変換しません。変換は数詞の連続部分に適用します。送信対象外の文字は□で表示し、音・ライト・WAV生成時は□自体の符号と間隔を送信しません。入力に元からある空白は保持します。TXT読込時は入力欄にも変換を反映し、手入力中は確認用表示に反映、送信確認時に入力欄も更新します。実際に送る文章と除外数を確認してから送信します。除外後に送信可能な文字がなければ送信しません。300符号を超える文章も読み込めますが、送信時に理由を表示します。受信結果の不明符号を示す□は従来どおり保持します。空ファイル・不正な文字コード・バイナリデータ・64 KB超過では理由を表示して取り込みを中止し、前の文章を保持します。送信時の300符号上限（濁点・半濁点は別符号として計数）は維持します。読み上げや漢字の読みへの変換は行いません。Word・PDFファイルは対象外です。小書きと改行は読み込んだ入力欄では保持し、送信確認時に従来どおり符号用に変換します。

## 通話で使う際の現在の範囲

音声送信は端末のスピーカーへの再生です。電話回線への直接挿入は実装していません。同一端末で再生した音が通話相手へ届くかは未確認です。

スピーカーフォンでも、通話中はAndroidがアプリのマイク入力を無音化する場合があります。通話中のリアルタイム受信は実機確認待ちです。制限される場合は、AQUOSの通話録音をエクスポートして取り込みます。

AQUOS R10の操作案内：設定 → AQUOSトリック → 迷惑電話の対策 → 録音リスト → 通話録音・ハイライト → 対象録音 → メニューからエクスポート。詳細は[シャープ公式FAQ](https://sharpmobile.zendesk.com/hc/ja/articles/48663493160473)を参照してください。実際の書出し形式は端末で確認が必要です。ファイル読込はAndroidの音声デコーダーに依存し、全MP3/M4A/WAVの互換性を保証していません。

## 初期版の制約

- 動画はAndroid標準の動画デコーダーに依存します。全形式を保証しません。MP4を推奨し、画素を取得できない場合はエラーを表示します。
- 動画内の光源は中央に置いてください。任意位置の範囲指定・追跡は未実装です。枠全体の平均輝度で判定するため、小さい光源や手ぶれには向きません。
- 動画の点滅はフレームの時刻で判定します。フレーム間隔が短点時間の65%を超えた場合は不連続として□を残します。短点時間の1/5より長い間隔は警告します。動画末尾の不完全な点灯を推測で補完しません。
- 0.3.1ではR10で送受信タブの操作と合成MP4の復号・認識を確認しました。実撮影動画の認識精度や全形式の互換性は未確認です。

- 送信と受信は切り替えて使用します。アプリを離れる・画面を消す場合は処理を停止します。
- カメラは中央固定の範囲の明るさを使います。自由な範囲選択、自動追跡、速度・音程の自動推定は未実装です。
- カメラの自動露出、反射、照明のちらつき、フレーム欠落に影響されます。プレビューは軽量な白黒表示です。
- 音声の雑音しきい値は固定です。周囲の雑音からの自動調整は今後の課題です。
- AQUOS R10（SH-51F）へのインストールと起動、合成PCM16 WAV3件の認識を実機で確認しました。通話録音の実ファイル・マイク・ライト・カメラの動作と精度は未検証です。
- 日本語・縦画面向けの試作です。iOS版は未実装です。

## 開発環境と再ビルド

本PCでは `.toolchain` にJDK17、Android SDK35、Gradle8.11.1を配置しています。Android Studioの導入は不要です。標準のJava環境を書き換えていません。

`tools/build.py` をPythonで実行するとAPK作成とAndroid Lintを実施し、成功時に `dist` へコピーします。`tools/test_core.py` は符号・合成音のテストです。既存Windowsプロジェクトの符号表を読み取り比較します。`tools/setup_environment.py` は環境準備用で、インターネット接続が必要です。

主なプログラム：`MorseCodec.java`（符号・時間判定）、`AudioEngine.java`（音声入出力）、`OpticalEngine.java`（ライト・カメラ）、`MainActivity.java`（画面・権限・停止操作）。いずれも `app/src/main/java/jp/local/wabun` にあります。

## 次の実機テスト

1. APKをインストールし、起動・権限拒否・許可・停止・再開を確認。
2. 「こんにちは」「がっこう」「ぱぴぷぺぽ」「（123）」のWAVを保存し、同じ設定で読み込む。比較対象は送信前に表示された正規化後の文章。
3. 別機器の音をマイクで受け、各速度で原文・結果・修正文字数・処理失敗を記録。
4. AQUOSの通話録音を書き出し、形式・会話区間除外・認識結果を確認。
5. 通話中のマイク無音化と、送信音が相手へ届くかを別々に確認。
6. 2台の端末で光を送受信し、距離・周囲の明るさ・短点時間・最大フレーム間隔・認識結果を記録。

音と光を別々に評価してから採用速度を決定します。合成テストの成功を実機性能として扱いません。

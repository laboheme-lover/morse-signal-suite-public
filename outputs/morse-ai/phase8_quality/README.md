## データが用意できたら

音声（WAVまたはMP3）と正解文（UTF-8テキスト）をペアで用意します。正解は認識結果を見て書き換えず、分からない箇所は別途記録してください。括弧はモード制御用で本文文字数に含めません。原稿に括弧がない欧文小数など、モードが曖昧な箇所は別途注記し、採点前に扱いを固定します。

`manifest_template.json` を別名でコピーし、`entry_example` を参考に `recordings` 配列へ登録します。`group_id` は同じ収録回・元動画などのまとまりです。`declared_unseen` は過去の開発・学習・調整・評価に使っていないことを確認してからtrueにします。

プロジェクト `morse-ai` のフォルダで実行します。

```powershell
.\.venv\Scripts\python.exe -B -X utf8 phase8_quality/intake.py 新規データ/manifest.json --output 新規データ/intake_audit.json
.\.venv\Scripts\python.exe -B -X utf8 phase8_quality/freeze_plan.py --verify
```

受入チェックは全音声のデコード、空ファイル、非有限値、必須項目、音声SHA-256、正規化正解文の重複を確認します。過去の44録音と合成データの音声ハッシュ、44件の原稿を照合します。未採点録音を含む全既存資料を網羅するものではなく、再圧縮・切り出しの同一音声も自動判定できません。出典と過去の利用履歴は人による確認が必要です。既知原稿の新録音は別の耐性評価には使えますが、この独立集合からは分けます。

### 新規推論の実行処理（追加整備済み）

`evaluate_new.py` は音声を新しく読み込み、区間検出→M1〜M4推論→モード処理→採点→モデル別・収録グループ別集計を行います。モデルの再学習・選択はしません。過去の区間境界を読み込まず、同じ新規検出結果を4モデルで共有します。

マニフェストの `source_review_completed` は出典・利用履歴を人が確認してからtrueにします。各録音の `body` を、予測を見る前に以下のいずれかへ設定します。

| 指定 | 使う状況 | 処理 |
|---|---|---|
| `{"mode":"full"}` | 音声全体が採点対象 | 全区間を処理。自動で挨拶文などを取り除かない |
| `{"mode":"protocol"}` | 通信開始・終了の符号がある | 一意のホレ／ラタ、または先頭HR HR BT・末尾ARで本文を選択。曖昧な場合は失敗として記録 |
| `{"mode":"window","start_seconds":10,"end_seconds":60}` | 本文の時間範囲を事前に確定できる | 指定範囲内の文字を処理。境界が文字の途中なら失敗として記録 |

```powershell
.\.venv\Scripts\python.exe -B -X utf8 phase8_quality/evaluate_new.py 新規データ/manifest.json --output phase8_quality/new_evaluation_001
```

通常実行は受入監査を再実施し、手動確認・未見宣言・重複チェックの条件を満たさないデータを拒否します。モデルと処理コードのハッシュも前後に照合します。出力先が存在すれば停止します。`report.md`、`summary.csv`、録音別の認識文・予測候補・時刻・編集対応、`group_summary.json` を保存します。

デコード・区間検出・推論の失敗は空の認識文として参照文字の全削除に数え、失敗件数も併記します。正常終了は終了コード0、評価中に処理失敗があれば2です。受入・ハッシュ検査で停止した場合は評価完了とは扱いません。
